# TransitIQ Data & Interface Contract (v2: SQLite)
Time = **simulated minutes from 00:00** (08:00 = 480). Distances in **metres**.
One name per concept: `vehicle_id`, `route_id`, `stop_id`, `trip_id` (never `bus_id`).

## Storage
- Database file: `data/transitiq.db` (SQLite). One table per dataset, **table name = dataset name** below.
- All modules work on **pandas DataFrames**. Read and write tables only through `backend/db.py`
  (`read_table(name)`, `write_table(df, name)`, `load_all()`). Open a fresh connection per call (Streamlit is multi-threaded).
- Keep a CSV export of every table in `data/` (generated by `export_csv.py`) for reproducibility and judges.
- The optimizer's candidate plans are **never** written to the DB (in-memory only). Only the final chosen plan and metrics may be saved.

## Tables
Column types matter: numeric columns must be INTEGER/REAL, not TEXT.

```sql
CREATE TABLE stops (stop_id TEXT PRIMARY KEY, name TEXT, x REAL, y REAL);
CREATE TABLE routes (route_id TEXT, seq INTEGER, stop_id TEXT, seg_time_min REAL,
                     PRIMARY KEY (route_id, seq));          -- seg_time_min = timetable minutes from previous stop; 0 at seq 0
CREATE TABLE vehicles (vehicle_id TEXT PRIMARY KEY, capacity INTEGER, available INTEGER,  -- 1/0
                       depot_stop_id TEXT, allowed_routes TEXT);                          -- allowed_routes optional, e.g. 'A;B'
CREATE TABLE schedules (trip_id TEXT PRIMARY KEY, vehicle_id TEXT, route_id TEXT, departure_time REAL);
CREATE TABLE passenger_demand (route_id TEXT, stop_id TEXT, window_start INTEGER,        -- 30-min windows
                               passenger_count REAL, day INTEGER);                       -- day optional (history)
CREATE TABLE gps_traces (vehicle_id TEXT, trip_id TEXT, timestamp REAL, x REAL, y REAL); -- optional
```

Scenarios stay in `data/scenarios.json` (or a `scenarios` table with `scenario_id`, `json` TEXT; agree one and tell the team).

## Scenario dict
```json
{"unavailable_vehicles": ["B1"],            // or {"B1": 495} = unavailable from 08:15
 "demand_multiplier": {"S1": 1.4},          // or {"*": 1.2} for all stops
 "route_delays": {"B": 6}}                  // minutes added at trip start
```

## Simulator function (simulation.py, owned by sim teammate)
```python
run_simulation(schedules, vehicles, demand, routes, scenario=None, seed=42) -> dict
```
Inputs are DataFrames with the columns above (loaded from the DB). Must be **deterministic** for the same inputs and seed, **fast** (<0.1 s; the optimizer calls it ~200x), and must **skip trips of unavailable vehicles**. Returns DataFrames:
- `arrivals`: trip_id, vehicle_id, route_id, stop_id, seq, scheduled, actual   (one row per trip x stop)
- `occupancy`: trip_id, stop_id, seq, onboard, boarded, left_behind  (+ vehicle_id, capacity optional)
- `waiting`: stop_id, passengers, wait_min   (wait per passenger of that group)
- `unserved`: route_id, stop_id, window_start, passengers   (demand in windows with no trip at all; empty if none)

Reference implementation: `tests/mock_sim.py` (same contract).

## Functions the algorithm side exposes (used by orchestrator.py)
| Module | Call | Returns |
|---|---|---|
| eta_engine | `evaluate_eta(history_arrivals, routes)` -> `["model"]`, MAE numbers | dict |
| eta_engine | `predict_all_etas(model, arrivals, current_time)` | DataFrame (eta, eta_lo, eta_hi, predicted_delay) |
| demand_engine | `build_demand_model(demand)`, `forecast_trip_loads(schedules, ctx, model)`, `forecast_unserved(...)`, `rank_routes_by_excess(loads, unserved)` | DataFrames |
| risk_engine | `detect_risks(loads, etas)`, `summarize_alerts(alerts)` | list[dict], KPI dict |
| optimizer | `optimize_plan(run_sim, schedules, ctx, hot_routes=[...])` | result dict (below) |
| constraints | `PlanContext(...)`, `validate_plan(schedules, ctx, sim=None)`, `cancel_unavailable_trips` | dict / tuples |

### optimize_plan result keys
`status` (improved | no_improvement | no_feasible_candidates | no_action_needed), `message`, `actions[]` (description, reason, tradeoff, constraints_satisfied), `baseline_metrics`, `optimized_metrics`, `comparison[]` (metric, baseline, optimized, improvement_pct, better), `original_plan[]`, `proposed_plan[]`, `cancelled_trips[]`, `validation` {feasible, details{check:{ok,violations}}}, `candidates_evaluated`, `candidates_rejected`, `rejection_examples`, `_baseline_sim` / `_optimized_sim` (DataFrames for charts).
